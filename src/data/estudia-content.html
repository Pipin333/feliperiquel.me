TORPEDO AED (PTEC101): PUNTEROS C, TDA Y LISTAS DINÁMICAS PLANA 1
ALERTAS DE SOLEMNE 1 Y CONTROL 1

Orden estricto al insertar M: primero conecta M->sig al resto de la lista y luego apunta el predecesor a M. Si haces L->sig = M antes, pierdes el resto de la lista.

Orden estricto al eliminar sin fugas: guarda en aux, salta el enlace (prev->sig = aux->sig) y recién al final ejecuta free(aux); aux = NULL;.

Al crear con malloc: inicializa siempre ->info y deja ->sig = NULL para no apuntar a basura.

TORPEDO AED (PTEC101): GRAFOS EN C Y ÁRBOLES BINARIOS (AB / ABO) PLANA 2
GRAFOS Y MATRIZ DE ADYACENCIA

$G = (V, A)$ en C como matriz int **Grafo ($O(V^2)$, consulta arco en $O(1)$). No dirigido es matriz simétrica ($G[i][j] = G[j][i]$). Completo no dirigido tiene $n(n-1)/2$ arcos.

  • Grado de entrada de x: contar G[i][x] != 0 (columna x, antecesores).
  • Grado de salida de x: contar G[x][i] != 0 (fila x, sucesores).
  • Sumidero (C2): entrada > 0 && salida == 0.
  • Fuente: entrada == 0 && salida > 0.
  • Lazo: G[x][x] != 0. k-regular: todo nodo con grado $k$.
DFS, BFS Y DIJKSTRA

DFS (Profundidad): recursivo / Pila, explora por menor índice no visitado. Profundidad(w); return Visitados[z]; verifica si existe camino de w a z.

BFS (Amplitud): usa Fila (FIFO) por niveles de distancia.

Dijkstra (pesos $\ge 0$): #define infinito 10000000, arreglos Costo[], predecesor[] y Visitados[]. Toma el nodo no visitado con menor Costo[u], marca visitado y relaja:

$$\text{Costo}[u] + G[u][v] < \text{Costo}[v] \Rightarrow \text{actualizar}$$
ÁRBOLES BINARIOS (AB): CONCEPTOS
struct nodoAB {
    int info;
    struct nodoAB *izq, *der;
};
typedef struct nodoAB *AB;
  • Peso: total de nodos $n$. Hojas: izq==NULL && der==NULL.
  • Interiores: nodos no hojas. Grado 1 / 2: 1 hijo / 2 hijos.
  • Altura (Control 3): máximo número de niveles desde la raíz a una hoja (raíz = nivel 0 al medir nivel con ALG3).
  • Llamadas recursivas (Act. 10): recorrer todo el AB deteniéndose en T == NULL ejecuta exactamente $2n + 1$ llamadas.
RECORRIDOS EN AB Y ABO
  • PreOrden: papá, izquierdo, derecho.
  • InOrden: izquierdo, papá, derecho. En un ABO entrega los elementos ordenados de menor a mayor.
  • PostOrden: izquierdo, derecho, papá (liberar nodos).
  • Por Niveles: usa Fila (FIFO), nivel por nivel de izquierda a derecha.
ABO: INSERCIÓN Y ELIMINACIÓN (F3 / F4)

Invariante ABO: subárbol izquierdo < raíz ≤ subárbol derecho. Insertar(A, dato) siempre crea una hoja nueva en $O(h)$.

Por qué evitar Formas 1 y 2: mover un subárbol completo debajo de una hoja del otro lado desbalancea fuertemente el ABO.

Eliminar con 2 hijos (Solemne 3):

  • Forma 3 ("menor de los mayores"): busca Menor(A->der) (ir todo a la izq), copia su valor a la raíz y elimina ese nodo original (tiene 0 o 1 hijo derecho).
  • Forma 4 ("mayor de los menores"): busca Mayor(A->izq) (ir todo a la der), copia su valor y elimina el original.

Regla de Solemne 3: si el ejercicio pide el recorrido tras insertar/eliminar y no dibujas el árbol final resultante, la pauta asigna 0 puntos.

Unidad 3 (Control 3, Actividad 10 y Solemne 3): Árboles Binarios (AB) y ABO

En Control 3 las definiciones se evalúan sobre un árbol concreto:

  • Peso: total de nodos ($n = 10$ en la pauta).
  • Altura: en Control 3 de PTEC101 se cuenta en niveles de nodos (raíz hasta hoja más lejana, p. ej. Altura = 5 para 5 niveles).
  • Hojas vs Interiores: las hojas cumplen izq == NULL && der == NULL; el resto son nodos interiores.
  • Regla de llamadas recursivas (Actividad 10): si una función visita ambos hijos hasta caer en el caso base T == NULL sobre un AB de $n$ nodos, se ejecuta exactamente $2n + 1$ veces (por ejemplo, $n = 11 \Rightarrow 23$ llamadas).

ALERTAS DE RETROALIMENTACIÓN

⚠️ Reducciones: $A \propto B$ significa $A \le B$ ($A$ más fácil que $B$).
• Probar $NP-Duro$: $\mathbf{[NPC\ Conocido] \longrightarrow [Nuevo]}$

⚠️ Poda: Las podas en Backtracking/B&B NO reducen la complejidad del peor caso ($O(n!)$ o $O(2^n)$).

⚠️ Casos Base: ¡Ojo con las condiciones límite en PD! Siempre define $DP[i, 0]$ y $DP[0, j]$ explícitamente.

ANÁLISIS ASINTÓTICO Y ORDENAMIENTO

Cotas: $O(g)$ sup ($\le$), $\Omega(g)$ inf ($\ge$), $\Theta(g)$ exacta ($=$).

Crecimiento: $1 < \log n < \sqrt{n} < n < n \log n < n^2 < n^3 < 2^n < n!$.

Propiedades: $\log(n^k) = k \log n$. $\log(n!) \approx n \log n$ (Stirling).

T. MAESTRO (DIVISIÓN)

$$T(n) = aT(n/b) + O(n^k) \quad (a \ge 1, b > 1)$$

  • Caso 1 ($a < b^k$): $T(n) \sim O(n^k)$
  • Caso 2 ($a = b^k$): $T(n) \sim O(n^k \log n)$
  • Caso 3 ($a > b^k$): $T(n) \sim O(n^{\log_b a})$

Paso: 1. ID $a, b, k$ ➔ 2. Calcular $b^k$ ➔ 3. Comparar $a$ vs $b^k$ ➔ 4. Elegir Caso.

INVARIANTES Y CORRECTITUD

Demostración formal de bucles:

  • Inicialización: Válido antes de iniciar (iteración 1).
  • Mantención: Si es válido antes de $i$, sigue siéndolo antes de $i+1$.
  • Terminación: Al terminar el ciclo, el invariante aporta una propiedad que demuestra la correctitud.
T. MAESTRO (SUSTRACCIÓN)

$$T(n) = aT(n-b) + O(n^k) \quad (a > 0, b > 0)$$

  • Caso 1 ($a < 1$): $T(n) \sim O(n^k)$
  • Caso 2 ($a = 1$): $T(n) \sim O(n^{k+1})$
  • Caso 3 ($a > 1$): $T(n) \sim O(a^{n/b} \cdot n^k)$

Paso: 1. ID $a, b, k$ ➔ 2. Comparar $a$ vs 1 ➔ 3. Elegir Caso.

PARALELISMO Y ARQUITECTURA

Aceleración & Ley Amdahl: $S_p = \frac{T_1}{T_p} \le \frac{1}{f + (1-f)/p} \le \frac{1}{f}$ ($f$: parte sec).

Métricas: Trabajo $W_p = T_p \cdot p \ge T_1$. Eficiencia $E_p = S_p / p \le 1$.

Modelos PRAM:
• EREW: Lectura/Escritura Excl.
• CREW: Lectura Conc, Escritura Excl.
• CRCW: Lectura/Escritura Conc.

Escritura Concurrente: Falso sin control. Requiere sincronización. Bernstein: $O_1 \cap O_2 = \emptyset$ (evita colisiones).

Mem. Compartida: Sincronización crítica (locks/semáforos) para evitar race conditions.
Mem. Distribuida: Memoria privada. Comunicación por mensajes (MPI).

TORPEDO ANÁLISIS Y DISEÑO DE ALGORITMOS (ADA) PLANA 2
DIVIDIR Y CONQUISTAR
Quicksort (Pivot Final)
quicksort(A, p, r):
  si p < r:
    q = particionar(A, p, r)
    quicksort(A, p, q-1)
    quicksort(A, q+1, r)

particionar(A, p, r):
  piv = A[r]; i = p - 1
  para j = p hasta r-1:
    si A[j] <= piv:
      i++; swap(A[i], A[j])
  swap(A[i+1], A[r])
  devolver i+1

Promedio $O(n \log n)$, Peor $O(n^2)$ si ya ordenado.

ESPACIO DE ESTADOS (TSP)
TSP con Backtracking (Poda)
buscar(c, vis, cost, ruta):
  si cost >= mejorCosto: retornar // PODA
  si |vis| == n:
    si existe c->orig:
      tot = cost + dist[c][orig]
      si tot < mejorCosto:
        mejorCosto = tot; mejorR = ruta
    retornar
  para vec no vis en ady[c]:
    vis = vis U {vec}; ruta.push(vec)
    buscar(vec, vis, cost + dist[c][vec], ruta)
    vis = vis \ {vec}; ruta.pop()

Worst $O(n!)$. **Branch & Bound:** Poda si $cost + cotaInferior \ge mejorCosto$. *Cota:* Sumar min 2 aristas incidentes c/nodo restante y div 2.

SELECCIÓN EN TIEMPO LINEAL

Mediana de Medianas: Encuentra el $i$-ésimo elemento de un arreglo dividiendo en grupos de 5 y usando recursión.

$$T(n) = T(n/5) + T(7n/10) + O(n)$$

Como $1/5 + 7/10 = 9/10 < 1$, por inducción es $O(n)$, evitando el peor caso de Quickselect.

RECETA DE 4 PASOS (PD)

Usa esto para asegurar puntos de desarrollo en PD:

  1. Definición: Sea $DP[i, j]$ la suma/ganancia óptima usando...
  2. Recurrencia: Ecuación de transiciones entre celdas.
  3. Casos Base: Valores límite (iniciales de filas/columnas).

Enfoques:

PROGRAMACIÓN DINÁMICA
LCS (Subsec. Común Más Larga)
LCS(X, Y, n, m):
  L = matriz (n+1) x (m+1) en 0
  para i = 1 hasta n:
    para j = 1 hasta m:
      si X[i] == Y[j]:
        L[i,j] = L[i-1,j-1] + 1
      sino:
        L[i,j] = max(L[i-1,j], L[i,j-1])
  devolver L[n,m]

Ecuación: $L[i,j] = L[i-1,j-1]+1$ si iguales, $\max(L[i-1,j], L[i,j-1])$ si no. $O(n \cdot m)$ tiempo y espacio.

Cambio Monedas (N° de formas)
formasCambio(D, n, C):
  formas = arreglo (C+1) en 0; formas[0] = 1
  para i = 1 hasta n:
    para monto = D[i] hasta C:
      formas[monto] += formas[monto - D[i]]
  devolver formas[C]

Ecuación: $T[i,j] = T[i-1,j] + T[i, j - D[i]]$. Optimizado a $O(C)$ espacio.

kadane(A, n):
  maxActual = maxGlobal = A[1]

    maxActual = max(A[i], maxActual + A[i])

Ecuación: $M[i] = \max(A[i], M[i-1] + A[i])$. $O(n)$ tiempo, $O(1)$ esp.

COMPLEJIDAD Y CLÁSICOS NPC
  • Vertex Cover $\propto$ Indep. Set: $V'$ es VC (toca toda arista) $\iff V \setminus V'$ es IS (no vecinos).
  • Indep. Set $\propto$ Clique: $V'$ es IS en $G \iff V'$ es Clique (grafo completo) en compl. $\overline{G}$.

• TSP: Ciclo hamiltoniano de costo total $\le K$.

Guía de Estudio Conceptual e Intuición

Explicaciones detalladas diseñadas para asimilar la lógica de los problemas antes del examen.

1. Reducciones Polinomiales ($A \propto B$)

La reducción polinomial se denota como $A \propto B$. Puedes imaginar la flecha como un signo menor o igual ($\le$) en términos de complejidad: A es a lo más tan difícil como B.

¿Cómo se razona?

  • Si el de la derecha ($B$) es FÁCIL: Entonces el de la izquierda ($A$) también debe ser fácil. (Si $B \in P$ y $A \propto B \implies A \in P$). Esto se usa para probar que un problema nuevo está en P.
  • Si el de la izquierda ($A$) es DIFÍCIL: Entonces el de la derecha ($B$) tiene que ser al menos tan difícil. (Si $A$ es NP-duro y $A \propto B \implies B$ es NP-duro). Esto se usa para probar que un problema nuevo es difícil (NP-duro).

⚠️ Trampa del Examen: Que $X$ sea NP-completo y $X \propto A$ no significa que $A$ sea NP-completo. Solo significa que $A$ es NP-duro. Para ser NP-completo, debes demostrar de forma separada que $A \in NP$ (es decir, que tiene un verificador de soluciones de tiempo polinomial).

2. La Esencia de la Programación Dinámica

Tanto Dividir y Conquistar (D&C) como la Programación Dinámica (PD) dividen el problema en subproblemas menores. La gran diferencia está en cómo son esos subproblemas:

  • Dividir y Conquistar: Los subproblemas son independientes. Ordenar la mitad izquierda de una lista en Mergesort no ayuda en nada a ordenar la mitad derecha. Se resuelven de forma aislada.
  • Programación Dinámica: Los subproblemas están traslapados (se repiten). En Fibonacci, calcular $F(5)$ requiere calcular $F(4)$ y $F(3)$, y $F(4)$ requiere $F(3)$ y $F(2)$. ¡El cálculo de $F(3)$ se duplica! PD resuelve el subproblema una sola vez y lo almacena en una estructura (arreglo/matriz) para leerlo en tiempo constante $O(1)$ la próxima vez.

Receta obligatoria para plantear PD:

  1. Definición del subproblema: Explica qué significa cada posición $T[i,j]$ en palabras.
  2. Ecuación de recurrencia: Cómo calcular $T[i,j]$ usando celdas anteriores.
  3. Casos Base: Cómo se inicializan las filas/columnas iniciales (límites). ¡No los olvides!
  4. Complejidad y Orden: El tiempo es proporcional al tamaño de la tabla (número de celdas por costo de llenar cada una).

3. Búsqueda en Espacio de Estados: Podas y Cotas

Para problemas difíciles como el Vendedor Viajero (TSP) de complejidad factorial $O(n!)$, no podemos evitar el peor caso, pero sí optimizar el caso promedio mediante técnicas de exploración:

  • Fuerza Bruta: Explora todas las combinaciones posibles sin importar nada.
  • Backtracking (Retroceso): Explora en profundidad (DFS). Lleva un registro del mejor costo global encontrado hasta el momento. Si en algún punto del camino el costo actual supera al mejor costo conocido, se poda esa rama (retrocede) porque cualquier avance adicional solo sumará costo.
  • Branch and Bound (Ramificación y Acotamiento): Explora usando una cola de prioridad (Best-First search) para ir siempre por el camino más prometedor primero. En cada nodo, calcula una cota inferior (estimación optimista del resto del camino). Si el costo acumulado + cota inferior $\ge$ mejor costo conocido, poda esa rama inmediatamente.

4. Entendiendo el Teorema Maestro

El Teorema Maestro por división calcula la complejidad de: $T(n) = aT(n/b) + O(n^k)$.

  • $a$: cantidad de llamadas recursivas que haces en cada paso.
  • $b$: factor de reducción del tamaño del problema en cada paso.
  • $n^k$: costo de dividir el problema y combinar las soluciones.

Comparamos la tasa de llamadas recursivas ($a$) contra la tasa de combinación ($b^k$):

  1. Caso $a < b^k$: La combinación y división al inicio domina el costo. Complejidad: $O(n^k)$.
  2. Caso $a = b^k$: Hay un equilibrio perfecto entre llamadas y combinación. Complejidad: $O(n^k \log n)$.
  3. Caso $a > b^k$: Las llamadas recursivas se multiplican muy rápido y dominan el costo. Complejidad: $O(n^{\log_b a})$.

Unidad 1 y 2: Búsqueda, Heurísticas, Adversarial y Metaheurísticas

1. Formulación y Búsqueda Clásica (BFS, DFS, UCS)

  • Modelo completo: Representación del estado, Estado inicial, Estado meta, Reglas de producción (acciones), Reglas de control (restricciones válidas), Costo de transición y Nodo $n = \langle \text{estado}, \text{padre}, \text{operador}, \text{profundidad}, g(n) \rangle$.
  • BFS (Cola FIFO): óptimo solo si todos los pasos tienen el mismo costo (minimiza profundidad).
  • DFS (Pila LIFO): poca memoria, no garantiza optimalidad ni completitud en espacios infinitos.
  • UCS (Cola de prioridad por $g(n)$): garantiza solución de costo mínimo con costos positivos.

2. Búsqueda Informada (A*) y Distancias

  • Evaluación: $f(n) = g(n) + h(n)$. Si $h(n)=0$ para todo $n$, A* se comporta exactamente como UCS.
  • Admisible: $h(n) \le h^*(n)$ (nunca sobreestima el costo real restante).
  • Consistente: para toda arista $u \rightarrow v$, $h(u) \le c(u,v) + h(v)$. Toda heurística consistente es admisible.
  • Grillas: Manhattan ($|\Delta f|+|\Delta c|$) es admisible solo con movimientos ortogonales; si se permiten diagonales de costo 1, sobreestima y la exacta es Chebyshev ($\max(|\Delta f|,|\Delta c|)$).

3. Minimax, Poda Alfa-Beta y Búsqueda Anytime

  • Poda Alfa-Beta: $\alpha$ es el piso ya asegurado por MAX (parte en $-\infty$); $\beta$ es el techo ya asegurado por MIN (parte en $+\infty$). Si $\alpha \ge \beta$, se podan los hijos restantes sin cambiar nunca la decisión final de Minimax.
  • Anytime: ante interrupción por tiempo, devuelve siempre la mejor acción de la última profundidad completada (nunca un resultado parcial). En estado terminal usa utilidad $U(s)$; en límite de profundidad usa heurística $E(s)$.

4. CSP y Metaheurísticas (Guía 1)

  • Clasificación CSP: Parcial (faltan variables) vs Completa (todas asignadas); Consistente (cumple todas las restricciones) vs Inconsistente (viola al menos una). En N-Reinas por permutación, hay conflicto diagonal si $|r_i - r_j| = |i - j|$.
  • Ascenso de colinas (HC): solo avanza si mejora estrictamente; se detiene en óptimos locales o mesetas.
  • Recocido Simulado (SA): $\Delta = f_{\text{nueva}} - f_{\text{actual}}$ (minimización). Si $\Delta \le 0$ acepta; si $\Delta > 0$ acepta cuando $r < e^{-\Delta/T}$.
  • Búsqueda Tabú (TS): prohíbe movimientos en lista tabú, salvo criterio de aspiración (si el movimiento tabú mejora estrictamente al mejor global encontrado hasta ahora).
  • Colonia de Hormigas (ACO): peso $w_i = \tau_i^\alpha \cdot \eta_i^\beta$, probabilidad $P_i = w_i / \sum w_j$, evaporación $\tau \leftarrow (1-\rho)\tau$.
  • Cruzamiento y Mutación en Permutaciones (TSP / N-Reinas): el corte directo de 1 punto rompe permutaciones (repite elementos y omite otros). Usar cruzamiento ordenado (copiar un segmento de P1 y rellenar los huecos con los elementos faltantes en el orden de P2) y mutación por intercambio (swap).

5. Molde de Solemne 1 (Bin Packing) y Facility Location (Guía 1)

  • UCS: Vector parcial $a$ con la asignación de cada objeto/cliente; regla de control valida capacidad $C$; costo suma contenedores usados o costos fijos + atención ($\infty$ si viola restricción).
  • Algoritmo Genético: Vector completo como cromosoma; Fitness con penalización $\infty$ si es infactible; Cruzamiento 1 punto $k \in [1, n-2]$; Mutación reasigna un gen si $\text{rand}() < \text{tasa}$.

Unidad 3: Lógica, Prolog, Planificación (PDDL) e Incertidumbre

1. Lógica Proposicional, FNC, Resolución y LPO

  • Agente Lógico: mantiene una Base de Conocimiento (BC) actualizada con TELL y consultada con ASK.
  • FNC y Resolución: FNC es una conjunción de cláusulas (disyunciones de literales). La regla de resolución elimina literales complementarios ($p$ y $\neg p$).
  • LPO: un predicado evalúa a verdadero/falso; una función devuelve un objeto del dominio. Sustitución aplica un reemplazo conocido ($x := a$); unificación busca la sustitución que iguala dos expresiones.

2. Prolog (Solemne 2: Investigadores)

participa(maria, orion). participa(nicolas, orion). participa(pilar, orion). colaboracion(maria, nicolas). companeros_proyecto(X, Y) :- participa(X, P), participa(Y, P), X \= Y. son_colaboradores(X, Y) :- colaboracion(X, Y); colaboracion(Y, X). ?- companeros_proyecto(pilar, X). % X = maria ; X = nicolas. ?- colaboracion(nicolas, maria). % false (hecho dirigido). ?- son_colaboradores(nicolas, maria). % true (regla simétrica).

3. Planificación Automática y PDDL

  • Modelo clásico $\Pi = \langle F, A, I, G \rangle$: una acción es aplicable si todas sus precondiciones se cumplen en el estado actual; sus efectos actualizan el estado (añaden hechos positivos y eliminan negativos).
  • Progresión vs Regresión: progresión busca hacia adelante desde $I$; regresión busca hacia atrás desde la meta $G$. Para diseñar heurísticas admisibles se usa un problema relajado (eliminando efectos negativos o precondiciones).
  • PDDL: divide en archivo de Dominio (:types, :predicates, :action con :parameters, :precondition, :effect) y archivo de Problema (:objects, :init, :goal).

4. Bayes y Redes Bayesianas

  • Test del Virus (normalización $\alpha$): con $P(i)=0.001$, $P(+|i)=0.99$, $P(+|\neg i)=0.02$: un positivo da $w(i)=0.00099$ vs $w(\neg i)=0.01998 \Rightarrow P(i|+)=4.72\%$. Dos tests positivos independientes dado $I$ elevan al cuadrado ($0.99^2$ vs $0.02^2$) $\Rightarrow 71.04\%$.
  • Red Bayesiana (DAG): cada nodo solo depende de sus padres: $P(s,\neg f,t,\neg d) = P(s)\cdot P(\neg f)\cdot P(t\mid s,\neg f)\cdot P(\neg d\mid t)$. Recuerda que $1-p$ solo invierte la variable a la izquierda de la barra dejando fijos a los padres.

2. Clustering (Min-Max, Jerárquico y DBSCAN)

  • Min-Max: $x' = \frac{x-\min}{\max-\min}$ evita que atributos de escala grande aplasten a escalas pequeñas en la distancia euclidiana.
  • Jerárquico Aglomerativo: Single ($\min$), Complete ($\max$) y Average (promedio).
  • DBSCAN ($\varepsilon, \text{MinPts}$): cuenta vecinos a distancia $\le \varepsilon$ incluyéndose. Core ($\ge \text{MinPts}$), Border ($<\text{MinPts}$ junto a un Core) y Noise (aislado).
